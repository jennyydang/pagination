Pagination component

The six required layouts below are static illustrations. Further down are two examples, both the exact same c-pagination markup, styling, and pagination.js — the only difference is whether the host page adds extra glue code. One is labeled SSR: just the component, dropped in with no extra JavaScript, its list/arrows/input all real server-renderable HTML from the first byte. The other is labeled AJAX: the same component, plus a few lines on the host page listening for its pagination:navigate event to keep a results list in sync without a full reload. Try clicking through pages, hovering an ellipsis, or resizing either example below ~800px to see the compact < 1 / 50 > mobile layout.

Example SSR

The exact same c-pagination markup, CSS, and pagination.js as the AJAX example below — just with no extra host-page JavaScript attached to it at all: no pagination:navigate listener, nothing. View source and you'll see the page list, the current page, and the disabled prev arrow are all plain, real HTML from the first byte — try disabling JavaScript entirely and every page number below still works via a normal full-page navigation to ?page=N. With JavaScript on, pagination.js takes over exactly as it does below: clicks push state and re-render in place, no reload.

Example AJAX

The same c-pagination component as the SSR example above (500 results, 10 per page, so 50 pages), except this page adds one thing: a listener on pagination:navigate. Clicking a page link, an arrow, the mobile input, or an ellipsis jump all fire that same event regardless; here it's used to re-render the results list below to match (no full page reload) while pagination.js itself still owns pushing the URL via pushState and re-rendering its own page list, exactly as it does in the SSR example.
